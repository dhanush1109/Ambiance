## What the hardware can actually do

Worth knowing before using the app, because the interface is built around it
rather than pretending otherwise.

The kit has **19 LED pieces**, but the controller firmware groups them into
**three zones** and cannot address a piece on its own:

| Zone | Name | Pieces | What it covers |
|-----:|------|-------:|----------------|
| 1 | Front cabin | 12 | 2 dash strips, 2 vent rings, all 4 door lines, all 4 door pockets |
| 2 | Handles & feet | 7 | 4 inner door handles, 3 footwell modules |
| 3 | All cabin | 19 | everything at once |

Consequences, all visible in the app:

- **One door cannot be its own colour.** Each door carries three pieces â€” its
  line and pocket follow Zone 1, its handle follows Zone 2.
- **Animations are global.** All 199 patterns run across the whole kit; they
  cannot be limited to a zone.
- **Brightness has ten steps** (0â€“9), which is why it is shown as ten segments
  rather than a smooth slider.
- **Nothing reads back.** The controller never reports its state, so the app
  shows what it last commanded. During an animation it shimmers rather than
  inventing per-piece colours it cannot know.

Full detail: [`../HYCROSS_ZONES.md`](../HYCROSS_ZONES.md) and
[`../PROTOCOL.md`](../PROTOCOL.md).

## One controller, by MAC

Ambiance is pinned to a single controller:

```
ATW-FWD-AAA6   7B:F7:38:62:BA:8A
```

**Connect by MAC** opens the link straight to that address. No scan, no device
list, no waiting on an advertisement â€” the lights come up in about a second.
It also means a neighbour's controller can never be reached by accident.

Scanning still exists under Settings â†’ Advanced, purely as a diagnostic for
checking range. Connecting to anything else is refused.

To change the controller, edit [`src/config/device.js`](src/config/device.js).

## Running it

### Android APK â€” the real thing

See [`../BUILD_APK.md`](../BUILD_APK.md). Bluetooth runs natively; nothing else
needs to be on.

### Desktop, with the car nearby

The Python bridge owns the BLE radio and the app talks to it over HTTP.

```
Start Ambiance.bat
```

Or by hand:

```powershell
$env:Path = "C:\Program Files\nodejs;$env:Path"
.venv\Scripts\python.exe server.py     # bridge on :8787
cd web ; npm run dev                   # app on :5173
```

### Desktop, no hardware

```powershell
$env:VITE_TRANSPORT = "mock"
npm run dev
```

Every screen works against a simulated controller that records frames.

## Layout

```
src/
  config/device.js     the pinned controller
  protocol/            frame builders, ported 1:1 from the Python â€” verified
  services/            transports (native BLE / bridge / mock), command queue,
                       reconnect, and controller.js: the only API screens use
  state/               zustand stores
  data/                pieces.js (the car), moods, effect gradients
  components/          CarHero, ColorField, Brightness, NavBar, cardsâ€¦
  screens/             Home, Moods, Effects, Favourites, Settings
  engine/              welcome fade, drift, time-of-day
  theme/               tokens.css, glass.css
```

**Design.** True-black OLED base so the car's glow is the only light on screen.
Blur is reserved for the navigation layer â€” tab bar, control dock, sheets â€”
following Apple's Liquid Glass guidance that glass belongs to navigation, never
content; cards are solid. Only the primary action is tinted, and the tint is
the live light colour, so the interface takes on whatever the cabin is doing.
The accent is registered with `@property`, which lets it *transition*: change
the cabin colour and the whole interface glides to the new tint over 400ms.

**Motion.** Everything is transform/opacity only, under 500ms, and gated on
reduced motion. The car draws its own outline once on launch; connecting â€” the
rarest event in the app â€” gets a single light sweep down the bodywork.
Haptics follow the same rarity rule: an 8ms tick for selecting a zone, 15ms for
applying a setting, and a three-part pattern reserved for connecting. They fire
only from press handlers and the connect success path, never from the command
layer, so a colour drag stays silent.

**Notes for future edits.** Writes are spaced 40 ms apart and coalesced per key,
so dragging a colour never builds a backlog. Zone 3 mirrors onto zones 1 and 2
because that is what the firmware physically does. The ambient engine stops on
any manual command, disconnect, backgrounding, or firmware animation â€” a stray
timer still writing colours after the driver takes over would be the worst bug
this app could have.
